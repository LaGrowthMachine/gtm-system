# Value propositions

The list of what the user's product is worth and can prove. Every page, ad and email draws from it. It lives in the
user's project, `landings/value-propositions.md`, and is updated there, never copied elsewhere.

**The rule**: a value proposition is written only if the capability is stated in a source the user controls (product
documentation, the public site, a product reference). **A proof is a capability or a named customer, never a rate.**

## How to write it

1. **Start from the big picture**: what the product is worth on the market, in one sentence the buyer would repeat.
2. **List the strengths that set it apart**, each with why it is hard to copy.
3. **Turn each strength into a value proposition**: the promise in the buyer's words, the proofs, where each proof is
   stated, and its role on a page.
4. **Write the rules of writing them**: what never gets written (a number of integrations, a plan, a rate).
5. **Note what the competitors also have**: those are not advantages.

Roles a value proposition can play on a page:

| Role | Where it goes |
|---|---|
| **Angle** | The H1 and the hero of a page built on it |
| **Argument** | A pillar of the 2x2 grid |
| **Reassurance** | Under the form or in the FAQ, never a title |
| **Call to action** | The offer itself (free trial, demo) |

## Template (copy it to `landings/value-propositions.md`)

```markdown
# Value propositions · <product> (<date>)

Sources: <product documentation, public site, product reference>, read on <date>.
Rule: a capability is written only if a source above states it. A proof is a capability or a named customer, never a rate.

## 1. What we are worth on the market
<One sentence the buyer would repeat.>

## 2. The strengths that set us apart
| Strength | Why it is hard to copy | Competitors who also have it |
|---|---|---|
| | | |

## 3. The value propositions
| # | Value proposition | The promise (buyer's words) | Proofs (checked) | Where each proof is stated | Role on a page |
|---|---|---|---|---|---|
| 1 | | | | | angle / argument / reassurance / call to action |

## 4. How we write them
- Never: <a number of integrations, a plan, a rate, ...>
- Always: <...>

## 5. Against competitors (pages and comparisons, never ads)
| Competitor | What they do well | Where they block | Sentence we can use |
|---|---|---|---|
```
